# Contributing to Veridex

Veridex is a **faceless, asynchronous, AI-native** project, and contribution
works the same way: everything happens in writing, through issues and pull
requests. There are no live meetings, no calls, and no real-time chat
requirement — propose your change in an issue or PR description with enough
context that a reader can evaluate it entirely offline. Keep PRs small and
focused; every rule or source-citation change must be explainable on its own
(the "no black boxes" standard applies to contributions too). Never include
real API keys, tokens, or personal data in any commit — reference secrets only
as `[ENV:VAR_NAME]` placeholders. New contributors: read `README.md`,
`docs/ARCHITECTURE.md`, and `SECURITY.md` first, then open a draft PR. Note
that this repository is an early-stage skeleton; expect rough edges, and please
do not add fabricated features, fake metrics, or unverified claims.
